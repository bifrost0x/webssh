# Trying the Go preview (M1)

M1 is a preview of the new Go server, not a release. It runs next to an
existing Python installation on its own port and its own volumes, offers
sign-in, the existing web interface, hosts and the SSH terminal, and reports
everything else as not available. Treat everything you do in the preview as
throwaway data: later preview builds re-migrate from the Python data instead
of keeping changes made in the preview.

All commands run from the repository root. The Compose files are
`deploy/docker/compose.m1.yml` and, for HTTPS, `deploy/docker/compose.m1.tls.yml`.

## What is where

| | Python | Go preview |
|---|---|---|
| Host port | 5000 | 5001 (`WEBSSH_GO_PORT`) |
| Port in the container | 5000 | 5000 |
| Container | `webssh` | `webssh-go` |
| Data volume | `<project>_webssh_data`, for example `webssh_webssh_data` | `webssh_go_data` |
| Recovery volume | `<project>_webssh_recovery` | `webssh_go_recovery` |
| Image | `ghcr.io/bifrost0x/webssh` | `webssh-go:m1` (built locally) |

The preview never mounts a Python volume. `docker volume ls` shows the exact
names on your host.

## Start with an empty volume

```bash
docker compose -f deploy/docker/compose.m1.yml up -d --build
docker compose -f deploy/docker/compose.m1.yml exec -it webssh-go /app/webssh create-admin --username <name>
```

`create-admin` asks for the password twice. Registration through the web page
is off in the preview (`BOOTSTRAP_REGISTRATION_ENABLED=false`), so the first
administrator always comes from this command. The old command form still
works and prints a deprecation notice:

```bash
docker compose -f deploy/docker/compose.m1.yml exec -it webssh-go /app/entrypoint.sh flask --app start:app create-admin --username <name>
```

Open `http://<LAN-IP>:5001` and sign in. To record the source revision in the
version shown after sign-in, build with
`WEBSSH_GO_VCS_REF=$(git rev-parse HEAD) docker compose ... up -d --build`.

## Start with a copy of existing Python data

The preview writes into its data volume (`go/` and `logs/.webssh-go/`), so it
always works on a copy. The Python volume is mounted read-only for the copy
and never again.

1. Stop the Python container. An open database journal or lock makes the
   migration stop.
2. Copy the volume. Do not create `webssh_go_data` beforehand: Docker creates
   it on first use and seeds it from the image, so it belongs to 1000:1000.

   ```bash
   docker compose -f deploy/docker/compose.m1.yml build
   docker build -f deploy/docker/Dockerfile --target debug -t webssh-go:m1-debug .
   docker stop webssh
   docker run --rm --entrypoint /bin/sh \
     -v <python-volume>:/from:ro -v webssh_go_data:/app/data \
     webssh-go:m1-debug -c 'cp -a /from/. /app/data/'
   docker start webssh
   ```

   `webssh-go:m1-debug` is the release image plus BusyBox, needed only for
   the copy. Python keeps running on its original volume from here on.
3. Optional: look at the migration report without migrating.

   ```bash
   docker compose -f deploy/docker/compose.m1.yml run --rm webssh-go migrate --dry-run
   ```

   Compose warns that `webssh_go_data` "already exists but was not created by
   Docker Compose"; that is expected after the copy.
4. Start the preview. The first start migrates the copy and logs
   `migration completed` with the path of the report.

   ```bash
   docker compose -f deploy/docker/compose.m1.yml up -d
   docker compose -f deploy/docker/compose.m1.yml logs webssh-go | grep -E 'data state|migration|kept in place'
   ```

The report is `/app/data/go/migration-report-<UTC>.json` in the preview
volume. Its `pending` list names the kinds of data this build does not
migrate yet (for example saved passwords, automation, command library,
directory identities). They stay untouched in the copy and are picked up by a
later build. `legacy_untouched.equal` must be `true`.

Existing accounts sign in with their passwords, TOTP and recovery codes.
Accounts managed by LDAP, OIDC or GitHub cannot sign in to the preview. If
the Python installation received `SECRET_KEY` from the environment instead of
the persisted `secret_key` file, the preview needs the same value, otherwise
it stops with "SECRET_KEY does not match the stored data" before writing
anything. Pass it through a local override that you do not commit, with the
value only in your shell or a secret store:

```yaml
# compose.m1.local.yml
services:
  webssh-go:
    environment:
      - SECRET_KEY
```

```bash
docker compose -f deploy/docker/compose.m1.yml -f compose.m1.local.yml up -d
```

### Taking a newer copy

A newer preview build or a fresh copy of the Python data replaces the preview
data; nothing made in the preview is carried over. Either repeat the copy into
a new volume (`docker compose -f deploy/docker/compose.m1.yml down -v`, then
step 2) or re-migrate the existing copy with the service stopped:

```bash
docker compose -f deploy/docker/compose.m1.yml stop webssh-go
docker compose -f deploy/docker/compose.m1.yml run --rm webssh-go migrate --replace
docker compose -f deploy/docker/compose.m1.yml up -d
```

`--replace` keeps the previous Go database under `go/replaced-<UTC>/`.

Never run `webssh legacy purge` on the preview. It removes the Python data
from the volume it runs on; the preview has no use for it.

## LAN access and HTTPS

Plain HTTP on port 5001 is enough for passwords, TOTP and the terminal.
Passkeys and secure cookies need HTTPS: over `http://<LAN-IP>` passkeys do not
work, over `http://localhost` they do. For HTTPS in the LAN add the Caddy
overlay, which issues a certificate from its own internal CA and serves
`https://<name>:5443`:

```bash
WEBSSH_GO_TLS_HOST=webssh.lan docker compose \
  -f deploy/docker/compose.m1.yml -f deploy/docker/compose.m1.tls.yml up -d --build
docker compose -f deploy/docker/compose.m1.yml -f deploy/docker/compose.m1.tls.yml \
  cp caddy:/data/caddy/pki/authorities/local/root.crt ./webssh-go-m1-root.crt
```

- `WEBSSH_GO_TLS_HOST` must be a name, not an IP address, and resolve to this
  host on every client (DNS or hosts file).
- Install `webssh-go-m1-root.crt` as a trusted root on each client. The CA is
  kept in the volume `webssh_go_caddy_data` (Compose prefixes it with the
  project name `webssh-go-m1`).
- With the overlay the plain port 5001 is closed; WebSSH accepts forwarded
  headers only from Caddy's fixed address.
- Passkeys migrated from Python work only under the name they were registered
  with. Use the same host name as the Python installation.

With rootless Docker and the default port driver of RootlessKit, WebSSH (or
Caddy) sees one internal address for every client: all LAN clients share the
per-address sign-in limits and the audit log shows that address.

## What works in M1

- Sign-in with password, TOTP, recovery codes and passkeys (HTTPS only),
  sign-out, password change, MFA setup and the recovery session for
  repairing factors; step-up with password, TOTP or passkey.
- Administration: account list, creating local accounts, feature gates with
  their preview of effects, `ADMIN_USERS`, and the CLI commands
  `create-admin` and `reset-password`.
- Hosts and jump hosts, SSH keys, host notes, workspace presets, host trust
  (known hosts, including the migrated global file).
- SSH terminal: password and key sign-in, jump hosts with keys, SOCKS5
  without login, host-key confirmation, reconnect after a page refresh,
  attaching to existing tmux sessions.
- Overview, start page, settings, themes and the six interface languages.

## What reports "not available in this preview"

A notice at the top of the page lists the missing areas; their entry points
are hidden and the server answers their routes with
`not_available_in_preview`. Nothing hangs and nothing is saved half-way.

- Files (SFTP), SMB shares, transfers, the editor.
- Saved passwords (`credential_id`), SOCKS5 with login, Tailscale SSH, the
  SSH gateway, multi-step keyboard-interactive prompts.
- Command library and command sets, automation, host discovery, server
  operations, Herdr. Herdr and start commands of a profile are not run; the
  terminal says so.
- Sign-in with LDAP, OIDC or GitHub; replacing legacy passkeys.
- Admin actions other than those listed above, backup and restore,
  operations views and the support report.
- `DEPLOYMENT_PROFILE=production`: the preview refuses to start with it.

## Back to Python

```bash
docker compose -f deploy/docker/compose.m1.yml down
docker start webssh   # if it is not running
```

The Python volume was only read for the copy and is unchanged. To remove the
preview completely, including its volumes:

```bash
docker compose -f deploy/docker/compose.m1.yml down -v
docker image rm webssh-go:m1 webssh-go:m1-debug
```

With the TLS overlay add `-f deploy/docker/compose.m1.tls.yml` to `down`.
`down -v` removes only the volumes of the preview files
(`webssh_go_data`, `webssh_go_recovery` and the Caddy volume), never the
Python volumes.

## Known limitations

- Preview data is throwaway. Later builds re-migrate from the Python data;
  changes made in the preview are not carried over.
- Host names with non-ASCII characters (IDNA) are refused; the migration
  report lists affected profiles.
- The ciphers `aes192-cbc` and `aes256-cbc` and the MAC `hmac-md5` are not
  supported; hosts that offer nothing else cannot be reached.
- Page routes outside M1 (for example `/automation`, `/credentials`) answer
  with a plain-text 501 instead of an HTML page.
- Under rootless Docker every client appears with one address (see above).
- The image embeds the full frontend, including terminal fonts and theme
  backgrounds, and is about 100 MB unpacked.
- Measurements of the preview are indicative only; the comparison with
  Python under quiet conditions is still open.
