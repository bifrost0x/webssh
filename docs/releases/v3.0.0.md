# WebSSH 3.0.0

Local release candidate. No release or image publication has been performed.

Version 3 introduces terminal-centered workspaces, integrated files, reusable
automation workflows and schedules, encrypted saved credentials, and a
per-account introductory tour.

## Highlights

- **Status-first overview.** Host readiness, open sessions, 14-day automation
  results, reachability and recent activity; an SSH route summary with the full
  topology map behind **Open map**. Each account arranges, resizes and hides the
  panels freely. **Needs attention** items can be dismissed and return when the
  situation changes.
- **Reachability checks** per account: off, on demand (default) or automatic.
  One TCP connection to the SSH port under the SSH network policy, no login.
  The greeting the server sends by itself gives direct hosts an unverified
  platform hint until a connection detects the platform.
- **Service detection.** Connected hosts report Docker, Podman, common system
  services and known container apps, read-only and at most once a week; the
  overview shows them on host cards and filters by them.
- **Find hosts.** Manual discovery of SSH and SFTP servers in a network range
  the user names, paced to about three attempts per second, with a prefilled
  new-host form. Controlled by `HOST_DISCOVERY_ENABLED` (off in production).
- **Automation** and **saved passwords**, administrator-controlled and disabled
  by default.
- **Security hardening:** per-account limits for second factors and password
  changes, realtime connections bound to the WebSSH origin, `no-store` caching
  for dynamic responses, stricter GitHub auto-provisioning in production.
- **Every interface language complete:** the built-in command library, the
  tour and the interface notifications are available in English, Vietnamese,
  German, French, Spanish and Chinese, with consistent terms in each language.

## Changed defaults

- `TOTP_ENABLED` now defaults to `true`; authenticator apps are offered unless
  disabled.
- `TMUX_ENABLED` now defaults to `true` (every earlier Compose file already set
  it); new sessions still do not start in tmux unless a host asks for it.
- The new overview is the default layout; the classic overview remains
  available under Settings → Preferences.
- Existing accounts see the version 3 tour once after login.
- With `CORS_ORIGINS=*`, realtime connections accept only pages served from the
  address used for WebSSH. Reverse proxies must pass the original Host header
  (see the upgrade notes); `SOCKETIO_ALLOW_ANY_ORIGIN=true` restores the old
  behaviour outside production.

## Upgrade and recovery

Preserve the complete persistent data and recovery volumes before upgrading.
Keep the previous image pinned by version or digest. Existing themes, accounts
and saved settings are retained. Review effective deployment overrides in Settings.

Exported backups deliberately exclude saved remote passwords and SSH keys.
They do not replace a complete pre-upgrade recovery snapshot. For rollback, stop
the new instance and restore its matching pre-upgrade volumes with the previous
image; do not assume a newer database is supported by an older executable.

## Outstanding release gates

Final CI, final-image security review and native ARM64 acceptance remain release
gates. Unresolved Debian/SQLite findings require the documented maintainer risk
decision described in the version 3 overview. PR preparation is not release approval.
