# WebSSH 3.3.1

WebSSH 3.3.1 shows what each saved host is for: a role, the detected system
and the services it runs, on the overview cards, in the host rail, in session
tabs and above each terminal. It also hardens sign-in, TOTP and Tailscale SSH,
fixes the findings of the 3.3.0 review and removes dead code paths.

3.3.1 is the last release of the Python server. WebSSH 3.4 replaces it with a
server written in Go and migrates the data of 3.3.1 on its first start. 3.3.1
stays available as the way back from 3.4: the `3.3` image tag and the branch
`release/3.3` keep pointing to it.

## Highlights

- **Host roles and services.** One bounded, read-only probe on connect reads
  the system, the virtualization, the platform markers and the known services
  and container images of a host. Only values that map to a fixed catalog
  entry or a strict pattern are stored. Each host gets a role such as
  Hypervisor, Backup, Storage, Container host or Monitoring; a role chosen in
  the host editor always wins. Detected services appear with their logos, and
  the overview search finds hosts by role, platform and service. See
  [Profiles, Jump Hosts and Commands](../wiki/Profiles-Jump-Hosts-and-Commands.md#host-roles-and-where-they-are-shown).
  (#377, #378)
- **Host rail by role.** The host rail can group hosts by their group or by
  their role; the choice is remembered in the browser. (#378)
- **Sign-in protection settings.** Settings → Administration →
  Authentication → Sign-in protection sets the failed-attempt limits per
  username and the IPv6 grouping prefix. Browsers that signed in before keep
  access through a known-device cookie while a username is under attack. See
  the [Configuration Reference](../wiki/Configuration-Reference.md#sign-in-protection-admin-setting).
  (#375)
- **Several instances on one host name.** `SESSION_COOKIE_NAME` and
  `REMEMBER_COOKIE_NAME` give each instance its own cookies. (#373)
- **Lighter pages.** Only English and the active language are loaded, the
  commands panel, terminal scrollbar and file list do less work on the main
  thread, and automation polls only while it is visible. (#374, #375)

## Security

- TOTP guessing is counted per account for sign-in and step-up separately,
  and login rate limits cover usernames across sources. (#375)
- While Tailscale SSH is enabled, **Block ordinary SSH to tailnet nodes**
  (on by default) refuses ordinary SSH connections and probes to Tailscale
  node addresses routed through the tailnet interface; IPv4-mapped forms are
  checked as well. See [Tailscale SSH](../wiki/Tailscale-SSH.md#ordinary-ssh-over-the-tailnet).
  (#375)
- Terminal hyperlinks open only confirmed `http` and `https` targets, and a
  remote clipboard request shows what it will copy. (#373, #375)
- Sign-in continuations must start with a single slash. (#373, #376)
- Administrator user and setting changes are recorded in the security audit
  log. Secret rotation is refused while `SECRET_KEY` comes from the
  environment. (#371)
- Administrators listed in `ADMIN_USERS` are marked in the admin panel and
  cannot be demoted there; listed names cannot be self-registered. (#376)
- Sessions left behind by failed connects are closed, and logout fails
  closed. Deleting the root or a path that resolves upward is refused. (#376)

## Fixes

- `RATELIMIT_ENABLED` and `ADMIN_PANEL_ENABLED` accept a lowercase `true`.
  (#371)
- A malformed download limit is reported as a configuration error, and
  secret rotation works with a read-only application root. (#373)
- Socket.IO events with surplus or missing arguments no longer fail. (#370)
- Registration and password validation messages are translated, and
  administrator dialogs close with Escape. (#373)
- Errors that were silently ignored are logged. (#376)

## Project maintenance

- The legacy server-to-server transfer path and other unused code are gone;
  security checks that existed several times now share one implementation.
  (#376)
- TOTP codes are computed with the standard library. (#376)
- ruff checks the Python sources; ESLint rules are stricter. (#375)
- The v3.3.0 delivery evidence is recorded. (#369)

## Upgrade and recovery

Existing Compose files, named volumes and bind mounts keep working; the image
still runs as UID/GID 1000.

- The first start adds four columns for failed TOTP attempts to the `users`
  table. Saved hosts gain fields for the role and the detected facts.
- Host detection on connect now runs as one read-only probe; a host whose
  platform icon is set by hand is not probed again.
- With Tailscale SSH enabled, ordinary SSH to Tailscale node addresses
  through the tailnet interface is refused by default, also when
  `SSH_ALLOWED_INTERNAL_NETWORKS` lists `100.64.0.0/10`. Turn off **Block
  ordinary SSH to tailnet nodes** to allow it again.
- `ADMIN_USERS` administrators can no longer be demoted in the admin panel;
  remove the name from `ADMIN_USERS` and restart first.

Rolling back to 3.3.0 on the same volumes is expected to work: 3.3.0 ignores
the new columns and keeps the new host fields unread. This is derived from
the code and was not run as a separate round trip.

To upgrade to 3.4 later, start from 3.3.1 and read
[Upgrading to 3.4](https://github.com/bifrost0x/webssh/blob/main/docs/wiki/Upgrading-to-3.4.md)
once 3.4 is published. To return from 3.4, run
`ghcr.io/bifrost0x/webssh:3.3` on the unchanged volume.

See [Upgrading, Rollback, and FAQ](../wiki/Upgrading-Rollback-and-FAQ.md).
