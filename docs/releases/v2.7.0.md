# WebSSH 2.7.0

Release candidate; publication and versioned container images are pending.

WebSSH 2.7 improves SSH authentication, persistent-session navigation, and
reviewable file operations, and includes security and dependency updates.

## Changes since 2.6.0

- Answer ordinary SSH server `keyboard-interactive` challenges, including PAM
  MFA after password or key authentication. Jump-host prompts identify the hop.
  This is separate from MFA for the WebSSH account. Quick SFTP retains its
  password/key authentication path. (#304)
- Follow folders in persistent tmux sessions with the existing synchronization
  toggle and explicit Bash prompt setup. The helper is activated manually in
  the intended shell, preserves prompt configuration, and does not edit shell
  startup files. Synchronization waits when the prompt is uncertain. (#300, #302)
- Use session-local tmux mouse scrolling and choose persistent sessions
  explicitly instead of having tmux preselected. (#293)
- Manage reusable commands more easily and preview bounded recursive SFTP
  permission changes before applying them. File and folder modes remain separate;
  SFTP chmod is still disabled by default. (#291)
- Keep existing command encodings compatible and validate profile startup modes.
  (#299)
- Match login and workspace branding to the selected theme, with responsive
  background scenes and updated product screenshots. (#292, #294)
- Harden remote protocol bounds, account storage access, backup coordination,
  and restore/maintenance fences. (#295, #296)
- Refresh Python, browser, container and CI dependencies, including pyasn1 and
  the development-only minimatch security fix; repair the disposable LDAP lab.
  (#295, #297, #307, #308)
- Distribute WebSSH under Apache License 2.0 with retained attribution and
  third-party notices. Bundled components keep their own licenses. (#298, #299)
- Shorten the README, retain detailed guides in the Wiki, and move the full
  screenshot gallery to [Screenshots](../screenshots.md).

## Upgrade notes

1. Back up the complete data volume, matching application secret, external
   authentication secrets and deployment configuration. Keep the previous
   immutable image digest for rollback.
2. Use Compose files from the same published release. Pin the image to
   `ghcr.io/bifrost0x/webssh:2.7.0` after publication, or use its verified digest.
   The default Compose file follows `latest`.
3. Recreate the service with your existing overlay list and persistent volumes.
   Reload already-open browser tabs to load the matching SSH authentication UI.
4. Check `/health`, `/ready`, local and configured external sign-in, stored keys,
   host-key trust, direct SSH, and a small SFTP transfer. Test PAM MFA against
   your server's actual authentication policy.
5. If using tmux folder synchronization, follow the explicit Bash activation
   instructions and confirm readiness at an empty prompt. It is opt-in and is
   not installed persistently on the remote host.

Exactly one Gunicorn `gthread` worker remains required. SMB, Tailscale SSH,
SFTP chmod and server mutations retain their explicit activation requirements.
Standalone SFTP does not gain interactive MFA. The 2.6 parameterized `argv`
command-set downgrade boundary still applies; changing the image alone does not
reverse stored formats. See [upgrade and rollback](../wiki/Upgrading-Rollback-and-FAQ.md),
[SSH authentication](../wiki/SSH-Connections-and-Host-Keys.md),
[tmux setup](../wiki/Terminal-and-Persistent-tmux-Sessions.md), and
[licensing](../licensing.md).

preparation does not certify deployment-specific identity-provider, device,
upgrade or recovery acceptance.
