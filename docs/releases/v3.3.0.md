# WebSSH 3.3.0

WebSSH 3.3 adds an optional Herdr integration for agent overviews and a Herdr
session mode, a command-line password reset for local accounts, and a round of
sign-in, session and SFTP fixes. The container moves to Python 3.15.

## Highlights

- **Optional Herdr integration.** Off by default and enabled by an
  administrator. The Overview board gains a read-only Agents panel for hosts
  that run agents in [Herdr](https://github.com/herdrdev/herdr) panes, and
  saved hosts can open Herdr as their terminal session mode instead of a shell
  or tmux. WebSSH only runs fixed commands on the existing SSH connection and
  treats everything Herdr reports as untrusted text. See the
  [Herdr guide](../herdr.md). (#354)
- **Password reset from the host.** `flask --app start:app reset-password
  --username <name>` sets a new password for a local account, including the
  only administrator. It ends the account's sign-ins and, while WebSSH is
  running, its open connections, SSH sessions, persistent tmux sessions and
  transfers within a few seconds. LDAP- and GitHub-managed accounts are
  refused. See
  [Forgotten password](../wiki/Users-and-Account-Management.md#forgotten-password).
  (#361)
- **Overwrite on SFTP upload conflicts.** Uploading a file that already exists
  in an SFTP folder shows the Overwrite / Skip dialog again instead of a generic
  failure. (#361, fixes #364)
- **SFTP and editor fixes.** Names such as `notes..txt` are allowed, files with
  mixed line endings keep them on save, Latin-1 files stay Latin-1, files opened
  through a symlink can be saved, very long names upload, and a directory with a
  non-UTF-8 name no longer breaks the listing. Running uploads and downloads
  survive a Socket.IO reconnect. (#360)
- **Terminal size and paste.** Terminals refit after a tab switch, minimised
  window or other short layout collapse instead of staying a few columns wide,
  and Enter confirms a reviewed paste. (#359, fixes #358)
- **Long-lived pages.** CSRF tokens stay valid for the whole session, so a tab
  open for more than an hour can still save. Terminal appearance and workspace
  presets ask for a reload when a page did expire. (#357)

## Security

- A locked account answers the correct password like a wrong one, so the lock
  no longer confirms a guessed password. (#361)
- New usernames are limited to ASCII letters, digits and underscores, which
  rules out look-alike names. Existing usernames stay valid. (#361)
- Locking, deleting, LDAP revocation, an MFA reset and a password change end
  the tmux sessions of connected terminals. A tmux session WebSSH cannot end,
  because it is detached or the host did not confirm the kill, is listed in the
  security audit log as `TMUX_SESSION_NOT_ENDED`. (#361)
- When the browser drops the `Secure` session cookie over plain HTTP, an error
  page names the cause, and the log warns once when traffic contradicts
  `TRUSTED_PROXIES`. Secure cookies remain the default. (#361)

## Upgrade and recovery

No database schema change. Existing Compose files, named volumes and bind
mounts keep working; the image still runs as UID/GID 1000.

Behaviour changes to check before upgrading:

- Signing out keeps persistent tmux sessions running on the host; they stay
  available as reconnect candidates. A password change still ends them.
- New accounts need ASCII usernames (`[A-Za-z0-9_]`).
- `SESSION_TIMEOUT` must be a positive integer. `0`, negative or non-numeric
  values stop the container with a configuration error; they never worked.
- `RATELIMIT_REAUTH` defaults to `10 per minute` instead of `5 per minute`.
  Deployments that set it keep their value.
- `MAX_UPLOAD_SIZE` is configurable, and `MAX_DOWNLOAD_SIZE` no longer follows
  it. Both still default to 100 MiB.
- The minimum for `BACKGROUND_WORKERS` rises by one because of a new background
  job. A lower explicit value is raised with a startup warning. Deployments whose
  `QUOTA_SSH_SESSION_GLOBAL` and `QUOTA_BACKGROUND_JOB_GLOBAL` already add up to
  the 128-worker ceiling stop with a configuration error.
- The container health check accepts Gunicorn on `PORT` or on 5000.
- `flask reset-password` refuses to run as root while the data directory
  belongs to another user. `docker compose exec` runs it as the container user.
- Staging files during writes are named `.webssh-<purpose>-<hex>.tmp`; the
  documented `.webssh-tmp-*` pattern still matches.

Rolling back to 3.2.0 on the same volumes is expected to work: 3.2.0 ignores
the new Herdr settings and host options and opens those hosts with a plain
shell. Hosts exported with Herdr options cannot be imported into 3.2.0. A
password-reset request still pending at rollback is not carried out by 3.2.0;
restart the container to end those connections.

See [Upgrading, Rollback, and FAQ](../wiki/Upgrading-Rollback-and-FAQ.md).
