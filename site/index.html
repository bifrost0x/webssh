Your first session starts here.

Start locally with Docker.

Docker · Bash / Zsh
docker run -d \
  --name webssh \
  -p 127.0.0.1:5000:5000 \
  -e CORS_ORIGINS=http://localhost:5000 \
  -v webssh_data:/app/data \
  --restart unless-stopped \
  ghcr.io/bifrost0x/webssh:latest

On the Docker host, open http://localhost:5000 and create your admin account. This command keeps the port on loopback; it is a local evaluation setup.

Before your first connection

A few useful answers.

What is WebSSH?

WebSSH is the MIT-licensed project maintained at bifrost0x/webssh: a self-hosted browser workspace for SSH terminals, SFTP files, saved connections and server administration. You install it on your own infrastructure and access that instance in a browser.

Is WebSSH free? Do I need a cloud account?

The software is free under the MIT license. You provide the infrastructure and pay any hosting costs. A hosted WebSSH subscription or account is not required. This website does not host SSH sessions.

Can I use it from a phone or another computer?

Yes. The responsive browser interface includes a mobile terminal workspace. Your device must be able to reach your WebSSH instance. Use a trusted network or VPN, or a properly configured HTTPS deployment for remote access.

Will my shell survive closing the browser?

Persistent shells use tmux on the remote server. With tmux available and persistence enabled for the session, you can return to the remote shell after reconnecting. Ordinary SSH sessions do not provide that guarantee, and browser sign-in still expires independently.

Can I expose the quickstart directly to the Internet?

The local quickstart is for evaluation. Internet-facing deployments require the production overlay, HTTPS, an exact browser origin, a restricted backend and an administrator created from the trusted host. See the production deployment path.

Where can I find documentation or get in touch?

Start with the documentation, check releases, or discuss ideas on GitHub Discussions. For project questions, email hi@getwebssh.com. For suspected vulnerabilities, follow the private reporting policy.
